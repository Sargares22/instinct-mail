# Instinct Mail

Позволяет агенту-программисту задать вопрос ИИ-ассистенту Instinct по email и проснуться при получении ответа. Один файл на Python для любого агентского харнесса на Linux, macOS и Windows.

[English version](README.md)

> [!IMPORTANT]
> Неофициальный проект сообщества. Не связан с Instinct и Google, не одобрен и не поддерживается ими. Служба поддержки Instinct не ответила, разрешено ли использование сторонних почтовых клиентов, поэтому совместимость с их Условиями использования не подтверждена. Используйте только с учетными записями, которые вы контролируете, на свой страх и риск.

## Зачем

Instinct - это персональный ИИ-ассистент, доступный по электронной почте. Он умеет искать информацию в сети, проводить исследования и возвращаться с ответом позже, но у него нет API и доступа к вашей машине. Агенты-программисты живут на вашей машине и отлично пишут код, но фоновые задачи по поиску информации быстро съедают их контекст.

Instinct Mail объединяет эти два мира. Агент пишет вопрос, отправляет его, продолжает работу и возвращается к треду, когда приходит ответ. Ответ приходит в виде обычного текста для чтения, а не строгих инструкций, которым агент обязан слепо следовать.

Типичные сценарии использования:
- Взгляд со стороны на план или архитектурное решение от кого-то, кто не погружен в кодовую базу.
- Исследования, требующие времени: сравнение библиотек, проверка лицензий или копание в документации.
- Проверка фактов перед принятием инженерных решений.
- Вопросы, которые вы бы и так задали в чате, но теперь их можно отправить прямо из рабочего треда.

## Требования

- Python 3.10+ (только стандартная библиотека)
- Аккаунт Gmail с двухэтапной аутентификацией и паролем приложения
- Email-адрес вашего агента Instinct
- Агент, умеющий выполнять команды оболочки

## Установка

Скажите вашему агенту:

> Установи Instinct Mail из https://github.com/Sargares22/instinct-mail по его README.

### Шаги для агента

1. Скачай этот единственный файл в одно и то же место на любой ОС:

   ```bash
   mkdir -p ~/.local/share/instinct-mail
   curl -fsSL https://raw.githubusercontent.com/Sargares22/instinct-mail/main/instinct_mail.py -o ~/.local/share/instinct-mail/instinct_mail.py
   ```

2. Выполни `python3 ~/.local/share/instinct-mail/instinct_mail.py doctor` (используй `python` или `py -3` на Windows). Команда выведет точную командную строку для текущей машины в поле `command`; используй ее в дальнейшем.
3. Создай `~/.config/instinct-mail/.env` на основе [.env.example](.env.example) и ограничь права доступа (только для владельца: `chmod 600`; на Windows `doctor` подскажет нужную команду `icacls`). Попроси человека самостоятельно вписать три значения. Не проси пароль в чате и не выводи содержимое файла на экран.
4. Выполняй `doctor` снова, пока `ready` не станет `true`.
5. Сохрани навык туда, где твой harness хранит навыки: `... instinct_mail.py skill > <каталог навыков>/instinct-mail/SKILL.md`. Если твой harness не поддерживает навыки, просто добавь одну строку в его файл с инструкциями (`AGENTS.md`, `CLAUDE.md`): «для связи с Instinct выполни `... instinct_mail.py skill` и следуй тексту».
6. Выбери способ пробуждения треда согласно таблице в тексте навыка.

Единственное, что тебе нужно понять про свой harness - это где он хранит навыки. Одна копия файла работает для всех агентов на машине; они используют общую конфигурацию и базу данных.

Для обновления: повтори шаги 1 и 5.
Для удаления: удали файл и навык; конфигурация и состояние останутся нетронутыми.

### Что предоставляет человек

Три настройки в `~/.config/instinct-mail/.env`:

- `GMAIL_ADDRESS`: ваш адрес Gmail
- `GMAIL_APP_PASSWORD`: 16-значный пароль приложения Google (не основной пароль от аккаунта)
- `INSTINCT_ADDRESS`: точный email-адрес вашего агента Instinct

## Как пробуждается тред

| Харнесс | Механизм |
|---|---|
| Claude Code | `wait --job JOB` запускается как фоновая команда; она завершается при получении ответа, и сеанс возобновляется. Проверено от начала до конца. |
| BB | `serve` работает как служба плюс уведомитель: `NOTIFY_BB=["bb", "thread", "tell", "{thread}", "{text}"]`, вопросы отправляются с `--notify bb --thread ID`. |
| Codex CLI | Не подтверждено. Агент проверяет `status` в начале хода. |
| Остальные | Запусти `doctor --probe 60` в фоновом режиме и заверши ход. Если тред возобновляется сам, используй фоновый `wait`; в противном случае проверяй `status`. |

Здесь нет обязательного фонового сервиса. Команда `serve` нужна только для тех harness, которые умеют отправлять сообщения в тред извне; примеры unit-файлов лежат в [contrib/](contrib/).

## Команды

- `ask`, `reply`: отправить вопрос или уточнение, возвращает ID задания (job ID)
- `wait`: заблокировать выполнение до появления непрочитанного ответа по заданию
- `read`: прочитать ответ; он помечается как прочитанный после вывода последней страницы
- `status`: посмотреть задания, непрочитанные и несопоставленные письма, а также время последней проверки ящика
- `sync`: разово проверить почту
- `serve`: опциональный сервис-приемник, который вызывает уведомители
- `doctor`: показать информацию об установке без вывода секретных данных
- `skill`: вывести `SKILL.md` для текущей установки
- `migrate`: обновить базу данных от предыдущих версий установки

Независимо от количества ожидающих агентов, проверка Gmail выполняется только одним процессом одновременно и не чаще, чем раз в `POLL_SECONDS` (60).

> [!NOTE]
> Фильтр безопасности ничего не блокирует; он лишь помечает подозрительный текст (`suspicious: true`). Текст из электронной почты всегда считается недоверенным. Подробнее см. в [docs/security-gate.md](docs/security-gate.md).
